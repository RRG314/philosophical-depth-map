# Integration with Philosophical Depth Map

The site's shared header links the original Depth Map, Reasoning Lab and Learn. The original exploration, knowledge map, journal, concepts, profiles and research material retain their routes and storage. `SiteRouter.tsx` lazy-loads each application; `#lab/*` routes own the Lab workflow and `#learn` owns the reading catalog. No Lab measure changes Depth Map XP, achievements or self-ratings.

Lab storage: IndexedDB `philosophical-reasoning-lab`, store `lab`. Original storage remains separate. Clearing Lab data does not clear Depth Map. Logs are versioned JSON, checked on import for schema, ordering, assignment and deterministic replay. Data files contain no secrets. Exported files are user-controlled and not erased by browser deletion.

Content boundary: `src/lab/data/problems.json` contains 60 intervention records and 18 assessment records. `lab/curation.tsv` supplies substantive intervention premises, assumptions, conclusions, objections and operations. `scripts/build_lab_bank.py` reproducibly packages these annotations and existing authored question text. This shared provenance is not independent psychometric validation and creates potential prior-exposure contamination.

Representation contract: `src/lab/core/schema.ts`. Propositions carry kind/source/grounding; argument edges are strict or defeasible; objections carry target and an explicit conditional-refutation flag; incompatible pairs, hypotheses and operational requirements are explicit. Actions contain prose plus structured commitments, definitions, admitted objections, outcomes and revision rationale. Prose is preserved but not parsed. Python CLI accepts `{problem,method,action,stage,previous}` on stdin (or a list). TypeScript and Python are tested for matching trace content.

Optional AI: existing hardened Worker exposes POST `/lab`, using `LAB_MODEL`, the same provider model and parameters for every method. Client sends method, problemId, stage, action, bounded history and explicit processing consent. Backend loads canonical question data and versioned protocol, validates structured output and enforces existing origin/rate/global-token budgets. No credentials are compiled into Vite. Set `VITE_AI_ENDPOINT` to the approved Worker origin and keep `OPENAI_API_KEY`, `LAB_MODEL`, `IP_HASH_SALT` server-side. Static GitHub Pages executes the browser TypeScript engine, never Python.

Future measurement exchange must use an explicit, consented adapter: source application, response ID, item/rubric versions, criterion, evidence, rater provenance and uncertainty. Do not map these eight dimensions to the original six by position. Do not infer personal proficiency or a deficit from session metrics. Research schemas remain separate; a coordinator may join approved identifiers only through an audited linkage table.
