# Architecture

React/TypeScript/Vite static application. Hash routes avoid server rewrite requirements on GitHub Pages subpaths. Accessible DOM forms and SVG were selected over an all-canvas interface because the brief explicitly requires keyboard/screen-reader support and long-form reading. The ocean is original vector artwork; no external fonts or image services are needed.

`src/lib/model.ts` owns versioned types, strict import schemas, rubrics, descriptive arithmetic, XP, achievement predicates and graph traversal. `src/lib/storage.ts` owns IndexedDB. App writes are serialized to avoid older snapshots overwriting newer drafts. `src/data/` contains content; the graph includes questions, concepts, illustrative positions, editorial arguments and objections. Contested edges are marked. Graph layouts are presentation choices, not logical proof. `App.tsx` contains route views and session orchestration; split route components as scope grows.

Knowledge = correctly answered applicable concept checks / observed concept checks. Reasoning = optional anchored self-ratings with exact evidence, item/rubric/rater/time provenance; no AI scores silently enter that profile. Exploration = unique questions, concepts, revisits and revisions, with deterministic XP. These are separate outputs. The assessment has a fixed ordered subset and fixed follow-ups; exploration permits user-selected angles. Recommendations combine unvisited items, same-domain interest, shared concepts and saved questions. They are navigation heuristics, not adaptive measurement or semantic diagnosis of reasoning gaps.

Local data flow: response → validated state → IndexedDB → user-directed export. No analytics or research transmission. AI flow, only if configured and consented: current text + item ID → separate Worker → provider → validated response. Raw answers are never written to application logs. `/evaluate` is a separate provisional endpoint with provenance; the public UI uses `/guide`. No research events are recorded. Research flow is deliberately disconnected until authorized authenticated infrastructure exists.

Worker accepts bounded JSON, validates Origin, checks consent and consumes atomic Durable Object reservations before external calls. Provider has no tools; untrusted text is explicitly separated. Structured outputs and exact-quote checks limit malformed scoring. They cannot prove model fairness or eliminate hallucination. Database schema uses pseudonymous IDs, versioned content, separate raw/derived tables, FK ownership and forced RLS. A custom DB setting only conveys an identity established by a trusted future service; it is not itself authentication.

No service worker: core play is independent of AI, but a first page load needs static assets from the host. There is no claim of installed/offline-first caching. Browser-origin changes require explicit export/import. Cross-tab editing is not synchronized; use one journal tab at a time. No remote account or sync success is fabricated.
