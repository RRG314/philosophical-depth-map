# Contributing

Read PROJECT_BRIEF.md and the construct/validity documents first. Preserve knowledge, reasoning and exploration as separate profiles. No ideological answer key, invented citation, inferred identity, empirical claim from synthetic data or automatic normalization of scores.

Items need stable IDs, explicit new versions for material edits, sources, eligible reasoning dimensions, fixed assessment follow-up, exploration alternatives and contrasting anchored examples. Add accessible prose, record editorial status honestly, and request independent philosophical/cultural review. Don't silently rewrite already recorded versions. Future migration code must preserve the historical item/rubric context.

Run `npm run check`, `npm run test:analysis`, and `npm run test:e2e`; database changes require disposable migration/isolation tests. Inspect desktop/mobile screenshots and reduced motion. Report exactly which checks ran. Changes to scoring, AI prompts, consent or study design need version increments and a documented interpretation review. Do not commit participant data, credentials, generated browser traces containing private answers, or local exports.
